# ADR-004: The Embed Script Is Loaded from jsDelivr

## Status

Accepted

Differs from Smarter Chat for WordPress's [ADR-003](https://github.com/smarter-sh/smarter-wordpress/blob/main/doc/adr/003-vendored-embed.md), which ships the script.

## Context

A theme app extension's `assets/` directory is flat (no subdirectories), and its files are served from Shopify's CDN under hashed names. `embed.js` loads Mermaid's chunks and KaTeX's fonts from an `embed/` directory beside itself, which a flat directory can't hold. Shopify's Theme Check also flags JavaScript assets over 10 kB in app extensions.

## Decision

The extension loads `https://cdn.jsdelivr.net/npm/@smarter.sh/ui-chat@<version>/dist/embed.js`, with an exact version, written once, in `snippets/smarter-chat-script-url.liquid`, which both blocks render, and which `make embed-version` updates. The tag is `async`, so it never blocks the page. Theme Check's `RemoteAsset` check, which recommends Shopify's CDN, doesn't flag the tag because its url is a variable; this ADR is the reason it is remote, and the check isn't disabled.

## Alternatives Considered

- **Ship `embed.js` in `assets/`, with `asset_url`.** Its `embed/` files can't follow it. It would work if the embed script could be told where its files are (a `data-assets` option, which it doesn't have today), at the cost of a 1.1 MB asset that Theme Check flags.

## Consequences

- **Positive:**
  - Nothing to build; the extension is Liquid only.
- **Negative:**
  - Visitors' browsers download the script from jsDelivr, a third party, which the store's privacy policy should mention.
  - Shopify's app review may ask for the script on Shopify's CDN; then the embed script needs a `data-assets` option first.
